## Что изменилось с прошлой пробы
- **`reasoning_effort=none`** отправляется у обеих моделей во всех вызовах пробы: ping 16 токенов, мини-схема 60 токенов. Диагностик больше нет, поэтому LLM-вызовов 4, а не 6.
- **Поиск:** ровно 2 логических запроса, RU и World. Каждый может сделать до 3 HTTP-попыток, повтор только после 5xx. Интервал между попытками не меньше 1,1 с, каждая попытка резервируется заранее.
- **Ошибка 5xx от прокси** (без request id Yandex) учитывается как `unknown`: сохраняется худшая оценка до сверки с Billing.

## Возобновление stage2 после технического сбоя (13.11.2026)

**Что произошло.** Первый stage2 (`trial:phase-b-pilot-01:stage2`, прогон 1) записан как `succeeded`, хотя аналитик получил HTTP 400: строгая схема была отклонена. Кандидат не оценён, скептик не запускался. По журналу 11,88 ₽, из них 7,79 ₽ `unknown`.

**Механизм** (код, миграция 009). Историю ничего не удаляет и не переписывает.
- **Статус `incomplete`.** Технический обрыв исследования до конца цепочки доказательств теперь даёт `incomplete`, а не `succeeded`. Обратного пути нет: это запрещает триггер БД.
- **Операция восстановления** `research:worker:recover`. Она работает только с БД, без сети и без денег. По сохранённым строкам она доказывает технический обрыв:
  - отзыв `quality_gate` «провайдер недоступен / ответ отклонён»;
  - 0 утверждений с вердиктом скептика;
  - 0 конкурентов;
  - 0 снимков.

  После этого она меняет только статус задания и пишет событие в `mr_job_events`. Попытки, журнал, оценки и источники остаются как были.
- **Возобновление = новый прогон** `trial:phase-b-pilot-01:stage2:r2`, отдельное задание.
  - Его бюджет — остаток потолка ступени после всех прогонов: 60 − 11,88 = **48,12 ₽**.
  - Общий бюджет испытания накопительный.
  - Старый прогон остаётся `incomplete` со всей историей.
